# Proof screenshots: DevOps Automation Toolkit

Run on 20 October 2026 from my laptop against a disposable test stack in AWS us-east-1.
The stack (7 Terraform resources: one t3.micro EC2 instance tagged `monitor=true`, a generated SSH key,
a security group allowing SSH from one IP only, and one S3 bucket) was created with `terraform apply`
and is removed with `terraform destroy` after testing (see `toolkit-test-infra/`).

My email address and the AWS account ID are covered with black boxes in the screenshots.

## Bug found and fixed during testing

The first real run crashed with `TypeError: cannot use a string pattern on a bytes-like object`.
Paramiko's SFTP file returns bytes, but the error filter expects text. The unit tests missed it
because they mocked the file read to return a string. I decoded the bytes in `read_new_log_lines`
and added a regression test that feeds bytes, like the real library does. The suite now has 44 tests.

## Scope and limitations

- The toolkit was run from a laptop against real AWS (SSO credentials, no stored keys). It was not deployed to Lambda.
- The SSH log check is meant to run locally. From Lambda it would need port 22 open to the internet or a VPC.
- The API check used placeholder endpoints, so it demonstrates detection of failures only.
- The S3 audit flagged only the missing lifecycle policy. New buckets are encrypted by default, so the encryption check did not trigger.
- The old-objects check (objects older than 90 days) was not demonstrated.
